# dsh-wechatbot · 微信机器人桥接

通过视觉识别实现 macOS 微信机器人，支持群聊和私聊。由 DSH 处理回复与会话记忆。

零注入。走 macOS 原生窗口 API、截图 OCR、系统通知库和剪贴板，不碰微信客户端进程。

## 它怎么工作

```
微信收到消息
   ↓
系统写入通知库 ──────┐
   ↓ fs.watch        │
检测到新消息         │  每 N 分钟兜底巡检（读屏）
   ↓                 │
   └────→ 跨源去重 ←─┘
            ↓
   一个对话窗口 = 一个真实 DSH 会话
            ↓
   sessionController.create + prompt
            ↓
   首轮带人设和职责，各轮带新消息、可选记忆和本轮截图
            ↓
        模型用 wechat_* 工具回复
            ↓
   静默 N 分钟后：压缩本窗口摘要进 MEMORY.md → 归档会话
```

关键点：机器人跑在**普通 DSH 会话**里，不是子 agent。会话归在
`dsh-wechatbot` 工作区，侧边栏能看到完整 transcript，支持归档、恢复和退出 DSH 后彻底删除。

## 安装

在 DSH 的插件页面选择「添加插件」，然后添加 `dsh-wechatbot` 本地目录。

### 首次配置

1. **授权**：系统设置 → 隐私与安全性
   - **辅助功能**：勾选 `DeepSeek Harness`（发送按键、拖动选区需要）
   - **屏幕录制**：勾选 `DeepSeek Harness`（截图 OCR 需要）

2. **选目标聊天**：在「概览 → 聊天配置」添加最多 10 个目标，每个目标单独选群聊或私聊。可使用「查找微信聊天」多选，也可手填完整名称。

3. **确认人设**：首次启动会把 `agent/template/` 复制到
   `~/.dsh/dsh-wechatbot/agent/`。要自定义就改那里的文档（见下）。

4. **启动机器人**：确认目标窗口后，在面板上点「启动」。

## 文档与记忆

工作目录默认 `~/.dsh/dsh-wechatbot/agent/`（可用配置项 `agentDir` 改）：

| 文件 | 作用 | 谁写 |
|---|---|---|
| `PERSONA.md` | 它是谁 | 你 |
| `AGENT.md` | 它该做什么 | 你 |
| `MEMORY.md` | 它记得什么 | 自动 |
| 其他 `*.md` | 额外风格文档，例如 `ANTI_AI_STYLE.md`，会一并进入系统提示词 | 你 |

注入策略：**每个新对话的第一条消息**里带上完整的 `AGENT.md` / `PERSONA.md`
（以及任何额外 `*.md`）。后续各轮带新收到的消息。跨会话摘要和本轮截图按设置附带。
人设和职责文档只在新对话的第一轮发给模型。

改文档后，**正在进行的对话**不会立刻变（它已经在上下文里了）；新开的对话生效。

## 工具

| 工具 | 作用 |
|---|---|
| `wechat_read` | 核对当前 DSH 会话中已收到、仍在屏幕上的消息。群聊优先拖选复制，失败时回退 OCR。私聊使用 OCR |
| `wechat_send` | 发一条 |
| `wechat_send_many` | 连发多条（更像人） |
| `wechat_stickers` | 查找已标注的微信收藏表情，按 ID 点击微信原生表情发送 |
| `wechat_send_image` | 按名字或路径发送本地图片 |

## 视觉与表情包

- **本轮截图**：开启 `attachScreenshot` 后，如果 OCR 能定位本轮首条消息，唤醒时会附上从该条消息开始的截图（默认缩到 1000px 宽）。
- **收藏表情**：在「机器人设置 → 表情管理」选择一个已配置聊天，点击「获取全部收藏表情」。可按标签、使用场景或标注状态筛选，支持 DSH 自动标注、手动编辑和删除插件库中的表情。缩略图和标签保存在机器人工作目录的 `stickers/`，升级时从旧库迁移。
- 面板预览默认关闭。点「截取一张」只截图一次，主动开启实时预览后约每 5 秒更新。退出概览或页面进入后台时会暂停。

## 插件页面板

在插件详情页的「概览」查看检测和目标窗口状态，在「机器人设置」修改检测、截图、回复及记忆参数。

跨会话记忆默认关闭，可在「高级设置」开启。「人格配置」可打开工作目录、预览当前 Markdown 文件，并导入替换后的副本。
「会话记录管理」提供按聊天筛选、归档、恢复和彻底删除。确认删除后，退出 DSH 让清理程序处理本地会话日志和投影，重新打开后核对结果。插件保存的摘要继续保留。桌面端通过已登录的 DSH 宿主访问 `/dsh-wechatbot/api`。

启动时的读屏记录和巡检只走后台 OCR。群通知缺正文、且确定要唤醒模型时，才会尝试拖选复制来补齐正文。面板的「会话与诊断」会显示最近一次读屏的原因、方式和失败详情。

## 已知障碍：微信防截屏

macOS 版微信会给自己的聊天窗口设置 `NSWindowSharingNone`（`kCGWindowSharingState = 0`），把窗口从所有截屏结果里剔除。这与权限无关，实测三种取像素的方式都拿不到窗口内容：

| 方式 | 结果 |
|---|---|
| `screencapture -l <窗口 id>` | 失败：`could not create image from window` |
| `screencapture -R <窗口矩形>`（显示器输出） | 截图成功，但窗口位置只有它背后的桌面 |
| ScreenCaptureKit 窗口捕获 | 返回纯白图 |

微信是 Mac App Store 版（App Sandbox + 硬化运行时，且没有 `get-task-allow`），所以外部没有公开接口可以改这个属性：调试器 attach 会被系统直接拒绝，注入也不成立。也就是说，**只要微信保持这个保护，任何依赖像素的能力都不可用**——OCR 读屏、本轮截图、收藏表情识别、拖选复制的锚点定位。

能绕开的只有两条：物理采集卡（在显示信号层，不受系统捕获管线的限制），或者降级为不依赖像素的运行方式。

### 降级运行

截图不可用时，读消息只能靠「手动指定拖选矩形 + 剪贴板」：拖选复制本身不需要截图，只有自动定位气泡需要。这部分目前**还没有接通**（读取路径仍然先取图做 OCR），计划中的做法是检测到 `sharing=0` 时跳过所有截图路径、改走固定矩形。

不受影响的部分：发送文字与图片、会话、记忆、配额、面板。受影响的部分：`wechat_read`、每轮截图、收藏表情、基于 OCR 的气泡定位。

## 注意

- 支持最多十个群聊或私聊，独立处理上下文，微信前台操作串行核对目标
- 发送前会校验群名，对不上就不发
- 每天主动发言有上限（默认 1000，@ 不计入）
- 群消息一律当作不可信数据，注入提示词的内容不会被当成指令执行
- 机器人用你自己的微信账号发言
