# 微信机器人桥接问题清单

## 新会话带入旧会话内容

已定位到记忆摘要和微信窗口中的可见历史。模型截图也可能带入同一窗口的旧内容。完整的旧 transcript 被复用这一点尚未复现。

跨会话记忆默认关闭，旧配置里保存的条数需要显式开启开关才会生效。条数设为 `0` 会同时关闭近期条目和长期摘要。`wechat_read` 只返回当前 DSH 会话已收到且能在屏幕上匹配的消息。模型截图从本轮首条能确认的消息开始，找不到唯一位置时跳过。本轮只有图片或表情且缺少可匹配文字时，也可能跳过截图。

## 会话移出后重回侧栏

旧操作会先移除归档标记，再直接删除本机日志和投影缓存。DSH 仍可从宿主状态显示这个会话，个别步骤失败也会被报告为成功。

面板的「移出工作区」先通过 DSH 归档，再解绑工作区。解绑失败会显示具体原因。下一次唤醒会检查归档状态和工作区成员关系。DSH 保留归档记录，支持切换归档筛选查看。已用模拟宿主验证侧栏归档、面板移出和解绑失败三条路径。

## 群聊拖拽复制漏掉末尾

自动拖选使用 OCR 文本框定位首尾。执行前校验微信在前台、窗口位置一致、主窗口仍打开目标聊天。如果剪贴板缺少可见首尾文本，自动模式回退到 OCR，手动坐标仍可用于有意读取指定片段。

模拟回归覆盖接近窗口底部的消息与剪贴板缺尾。仍需在不同尺寸的微信主窗口和独立聊天窗口里验证真实拖选。

## 微信防截屏导致视觉能力整体失效（未解决，硬阻塞）

微信会给自己的聊天窗口设置 `NSWindowSharingNone`（`kCGWindowSharingState = 0`）。当前安装的是 App Store 版 4.1.15，App Sandbox + 硬化运行时且没有 `get-task-allow`，外部没有公开接口能改回这个属性。

实测证据：

- `CGWindowListCopyWindowInfo` 读出该窗口 `sharing=0`；同进程的其他辅助窗口是 `1`
- `screencapture -x -o -l <id>` 失败：`could not create image from window`
- 全屏 `screencapture -x` 后在窗口矩形处裁切，只有窗口背后的桌面
- `SCScreenshotManager.captureImage`（ScreenCaptureKit）返回 960×625 纯白图
- `lldb -p <pid>` 被拒：`attach failed: Not allowed to attach to process`
- 辅助功能树只有一个 `AXWindow`、5 个节点，没有任何消息文本

影响：OCR 读屏、本轮截图、收藏表情抓取、拖选复制的自动锚点全部不可用。发送链路（剪贴板 + 快捷键 + 鼠标点击）不受影响，通知监听也不受影响。

处理：暂无软件解法。可选的只有物理采集卡（显示信号层），或降级为手动矩形 + 剪贴板读取（尚未实现）。
