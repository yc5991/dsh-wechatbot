# 微信机器人桥接问题清单

## 新会话带入旧会话内容（已解决）

已定位到记忆摘要和微信窗口中的可见历史。模型截图也可能带入同一窗口的旧内容。完整的旧 transcript 被复用这一点尚未复现。

跨会话记忆默认关闭，旧配置里保存的条数需要显式开启开关才会生效。条数设为 `0` 会同时关闭近期条目和长期摘要。`wechat_read` 只返回当前 DSH 会话已收到且能在屏幕上匹配的消息。模型截图从本轮首条能确认的消息开始，找不到唯一位置时跳过。

## 会话移出后重回侧栏（已解决）

旧操作会先移除归档标记，再直接删除本机日志和投影缓存。DSH 仍可从宿主状态显示这个会话，个别步骤失败也会被报告为成功。

面板的「移出工作区」先通过 DSH 归档，再解绑工作区。解绑失败会显示具体原因。下一次唤醒会检查归档状态和工作区成员关系。DSH 保留归档记录，支持切换归档筛选查看。已用模拟宿主验证侧栏归档、面板移出和解绑失败三条路径，并补齐 Windows 退出后彻底删除程序。

## 群聊拖拽复制漏掉末尾（已解决）

自动拖选使用 OCR 文本框定位首尾。执行前校验微信在前台、窗口位置一致、目标窗口未切换。如果剪贴板缺少可见首尾文本，自动模式回退到 OCR，手动坐标仍可用于有意读取指定片段。

## 微信防截屏导致视觉能力失效（已接通无像素降级模式 + Windows 4.x 支持）

macOS 版微信（如 App Store 4.1.15）会给聊天窗口设置 `NSWindowSharingNone`（`kCGWindowSharingState = 0`），导致 `screencapture`、区域截图与 ScreenCaptureKit 均拿不到窗口像素（甚至在 `-R` 区域截图中截穿到微信背后的桌面文字，曾引发发送前 `readComposerText` 误报“微信输入框中已有草稿”以及发图 `composerSignature` 恒不变化而中断）。

现已完成两方面处理：

1. **概览页「防截屏模式」开关与全链路免截图降级**：
   - 在「概览 → 微信窗口预览」卡片直接提供 **「防截屏模式」** 开关，并支持通过系统窗口属性（macOS `sharing = 0` / Windows `GetWindowDisplayAffinity != 0`）自动识别。
   - 开启或检测到窗口防截屏后：
     - **发送文字 / 发图片**：跳过输入框区域截图 OCR（`readComposerText`）与图像签名比对（`composerSignature`），依靠独立聊天窗口的原生标题、句柄、坐标与剪贴板读回进行严格核对。
     - **群聊读消息**：跳过前置 `captureChatRegion` 截图，直接在已核对的独立窗口消息区内按手动 `dragPoints` 或安全内缩矩形执行拖选复制 + 剪贴板解析。
     - **唤醒与巡检**：自动跳过每轮截图与截图巡检，提示用户先双击将目标聊天打开为独立窗口。
2. **Windows 微信 4.x (`Weixin.exe`) 原生支持**：
   - 新增 `lib/win-helper.cs` + `lib/wechat-windows.js` + Windows 通知库监听（`wpndatabase.db`），支持 UIA 控件树读取、拖选复制、WinRT OCR 与原生收藏表情收发。
