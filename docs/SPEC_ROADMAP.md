# dsh-wechatbot 后续演进路线图（Spec）

## Milestone v0.6.1+ · Plan B：双号读写分离中继架构（Observer → Sender Relay）

### 1. 背景与痛点
- 在 macOS 桌面微信 4.x 开启系统防截屏（`NSWindowSharingNone`）的环境下，单账号同时承担「读取群消息」和「发言」会遇到两类约束：
  1. 无法截取气泡/图片内容，仅能通过安全边距拖选复制读取纯文字；
  2. 同一微信账号高频切换群窗与拖选，可能增加客户端侧自动化特征暴露面。
- 当具备闲置电脑、无防截屏环境（如 Windows 桌面微信或未启用窗口保护的终端）或备用微信小号时，可采用**读写物理分离**方案。

### 2. 核心架构
将群聊工作拆分给两个相互独立的微信账号与 DSH 实例，通过本插件内置的轻量认证中继接口通信：

```text
┌────────────────────────────────────┐      局域网 / HTTPS      ┌────────────────────────────────────┐
│        观察节点 (Observer)         │    POST /relay/inbound   │         发言节点 (Sender)          │
│ · 使用微信小号在群里潜水观察       │ ──────────────────────▶ │ · 主力发言微信号全程静默不读屏     │
│ · Windows UIA / OCR / 高清看图截图 │   Bearer <relaySecret>   │ · 收到推送直接唤醒 DSH 并拟人发言  │
│ · 不发言、不抢键盘焦点             │                          │ · 无拖选、无截屏、最低客户端交互   │
└────────────────────────────────────┘                          └────────────────────────────────────┘
```

### 3. 协议与配置草案
- **新增工作模式 `relayMode`**: `'off' | 'observer' | 'sender'`
- **观察节点配置**：
  - `relayEndpoint`: 发言节点的局域网或内网穿透 URL（如 `http://192.168.1.20:PORT/dsh-wechatbot/api/relay/inbound`）
  - `relaySecret`: 共享 HMAC / Bearer 鉴权密钥（`0600` 持久化）
- **观察节点推送载荷**：
  - 经过 `DetectorService` 去重后的规范化消息（`groupName`, `sender`, `content`, `isAtMe`, `hasImage`, `sentAt`）与可选裁切后的低宽群聊截图（base64）。
- **发言节点安全边界**：
  - 校验 `Authorization: Bearer <relaySecret>` 与 `groupName` 白名单（必须在 `targets` 中存在）；
  - 通过共享 `selfEcho` 过滤防止回环自答，直接复用意图判定、记忆隔离与防检测拟人打字送出。

### 4. 其他候选方向
- **双向语音扩展**：基于 `silk-wasm` / 离线 ASR 补全无内置转写结果的语音消息，并探索可选语音回复。
- **跨平台剪贴板/热键精调**：按微信小版本变化持续校准 macOS / Windows 窗口控件特征与无障碍节点。
